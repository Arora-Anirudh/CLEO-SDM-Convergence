## 3. Numerical issue 1: an exact total near \(10^{19}\)

The configured concentration and \(10^{12}\,\mathrm{m^3}\) box imply:

```text
8388608000000000000 physical droplets
```

Float64 cannot distinguish every adjacent integer at this magnitude. The
first implementation multiplied float probabilities by the total, took floors
and summed them. It could lose hundreds of droplets because several different
large integers map to the same float.

The corrected implementation:

1. converts probabilities into high-resolution integer weights;
2. uses Python integers for quota floors and remainders;
3. gives residual droplets to the largest remainders;
4. breaks ties by bin index;
5. verifies the exact Python-integer total.

The final \(M_0\) total is therefore exact, not merely close within a relative
tolerance.

## 4. Numerical issue 2: nearly equal exponential values

With many narrow bins, directly calculating

```text
exp(-lower / scale) - exp(-upper / scale)
```

subtracts nearly equal numbers. At \(N_\mathrm{SD}=32768\), this could move a
calculated representative just outside its source bin.

The corrected bin integrals use:

- `expm1` for stable exponential differences;
- conditional first and second moments within a bin;
- series expansions for narrow dimensionless bin widths.

Float64 is used explicitly because NumPy `longdouble` has platform-dependent
precision. The scientific-array hash should not depend on whether the code ran
on macOS or Levante merely because one platform gives `longdouble` more bits.

The numerical sweep then passed for:

```text
64, 128, 256, 512, 1024, 4096, 16384, 32768 SDs
```

The 16-SD case was deliberately rejected because its \(M_6\) error was about
4.55%, above the registered 1% gate.

### Cross-platform hash finding

The gate also revealed a subtle but useful limitation. The macOS NumPy 1.26.4
scientific-array hash is `c2d02c94...551205`, while Levante NumPy 2.5.1
produces `11d4871d...c5d08`. Direct comparison found:

- 86 multiplicities with small integer redistributions while preserving the
  exact total;
- a maximum radius difference of `1.60e-18 m`;
- a maximum relative radius difference of `2.34e-13`;
- the same registered moment results to the checked tolerance.

The separate source-array and native-readback hashes also differ because CLEO
stores dimensionless radii and the reader re-dimensionalizes them. This is not
a physics-gate failure, but it means that “float64” alone does not promise
cross-platform byte identity. The permanent ensemble must generate each
resolution's bundle once on the pinned Levante stack and reuse that exact
native file after checksum verification.

### Bundle creation contract

One resolution gets one named, non-overwriting directory under the persistent
HOME bundle root. Input generation and native readback use the already
validated controlled path. Finalization requires:

- passing creation and native-readback schemas;
- matching \(N_\mathrm{SD}\);
- matching grid and superdroplet SHA-256 values across audit, readback and
  actual files;
- identical represented physical-droplet totals;
- all native readback gates true;
- a runtime configuration pointing at the exact bundle files;
- an initializer-source snapshot matching the creation audit.

The manifest records:

- a normalized scientific definition;
- project and pinned CLEO commits;
- Python, NumPy, platform, host and Slurm provenance;
- source and readback population fingerprints;
- relative path, size and SHA-256 for every required artifact.

Finalization removes write bits from every bundle file. An existing path or
manifest is never overwritten. A failed preparation remains visibly
incomplete and cannot pass `verify`.

### 17.3 Why the timestep screen was stopped before submission

The single pilot's formal fixed-bin L1 values at 3600 s were:

```text
250 bins:  0.2756078
500 bins:  0.3562021
1000 bins: 0.5346719
```

These values revealed a conceptual issue in the first screen analyzer. It
would have averaged scalar per-member L1 values. The registered scientific
estimand is instead:

```text
L1(ensemble-mean distribution)
```

and, because absolute value is nonlinear,

```text
L1(mean(g_j)) != mean(L1(g_j)).
```

The 25-member timestep screen was therefore **not submitted**. This was a
successful refusal gate, not a failed model run.

The corrected implementation:

1. saves every member's 250/500/1000-bin numerical and analytical arrays in
   `fixed_bin_distributions.npz`;
2. averages numerical distributions bin by bin;
3. computes L1 only after that averaging;
4. compares each timestep with 0.1 s using a deterministic 10,000-resample
   common-stream percentile bootstrap;
5. retains Student intervals for signed \(M_0\) and \(M_6\) member
   differences;
6. requires all registered times, bin grids, mass-drift and range-coverage
   gates to pass.

The same collision-stream labels are resampled together across timesteps to
make the comparison controlled and reproducible. The histories are still not
called paired because changing the timestep changes the collision-update
sequence.

Regression tests now include a deliberately constructed example in which both
members have L1 equal to 1 but their ensemble-mean distribution has L1 equal
to 0. The corrected repository passes:

```text

Bash parse: pass
pytest:     57 passed
```

The 25-row timestep matrix was regenerated from the corrected source
configuration. It remains metadata-only and records

The failed staging result is preserved under the persistent record. The cause

```text
decision-time range, |L1_250 - L1_500|:  0.0106 to 0.0222

```

This behavior is expected for a finite discrete superdroplet ensemble: finer
bins expose more histogram roughness. It is not evidence that the 0.1-s model
differs from itself.

With only that absolute cross-bin condition disabled in a read-only diagnostic
check:

- the 0.1-s reference passes every actual self-equivalence, conservation and
  range gate;
- none of 0.25, 0.5, 1 or 2 s has sufficiently narrow equivalence intervals
  at all registered times and bin counts;
- the conservative selected timestep is therefore 0.1 s.

ADR 0005 records the protocol amendment. The 500-bin statistic remains
primary; candidate-versus-reference equivalence must pass independently on
250, 500 and 1000 bins. Absolute cross-bin L1 differences remain reported but
are no longer independent acceptance gates. This tests stability of the
scientific decision without requiring identical scalar histogram noise at
different bin widths.

The cause is representational, not a failed scientific calculation. The


This is not a pipeline failure. The model, conservation, range coverage,

The main findings are:

- distribution L1 decreases systematically as superdroplet resolution rises;
- at 16,384 superdroplets, both relative \(M_0\) and \(M_6\) pass their
  accuracy and precision gates at all six decision times;
- the 16,384 primary 500-bin L1 at 3600 s is 0.04996, but its bootstrap 95%

- the 1000-bin L1 accuracy gate fails at every decision time even at 16,384;
- no adjacent pair passes the ±0.01 L1-difference interval at all required

- maximum liquid-mass drift is \(1.95\times10^{-8}\), safely below the
  \(10^{-7}\) gate;
- diagnosed out-of-range mass is zero.

The defensible conclusion is that bulk moments show strong high-resolution
agreement and the full distribution shows a clear convergence trend, but the
initial matrix does not establish formal distribution convergence. Any
extension of resolution, ensemble size, binning policy or distribution metric
must be pre-registered as a follow-up rather than retroactively changing this
decision.

## 23. Literature-grounded extension after the non-acceptance result

The researcher decided not to move to Long until the controlled Golovin
experiment formally establishes convergence and requested higher resolution
and more ensemble members. No Levante job was submitted during this review.

The four supervisor-prioritized papers, Shima et al. (2009), Dziekan and
Pawlowska (2017), Schwenkel et al. (2018), the current CLEO numerical-methods
paper and current primary online versions were compared directly with the
published 120-member result.

The literature supports the observed separation between already-stable bulk
moments and a more demanding fine DSD:

- Shima et al. show substantially improved Golovin agreement at 131,072
  superdroplets and identify right-tail sampling as a high-resolution issue;
- Unterstrasser et al. (2017) use 50 realizations by default and show that
  hundreds can be useful for smooth DSD statistics;
- Unterstrasser et al. (2020) obtain robust box-like averages from 1000
  statistically independent grid boxes;
- Morrison et al. use deterministic initialization and mostly 50-member
  ensembles, with spread decreasing approximately as
  \(N_\mathrm{SD}^{-1/2}\);
- Zmijewski et al. couple ensemble size to resolution, using approximately
  \(10^7/N_\mathrm{SD}\) realizations above 100 SDs, and find that mean DSD can
  converge while DSD variance continues to shrink through \(10^5\) SDs;
- Dziekan and Pawlowska and Schwenkel et al. use very large effective
  ensembles for distribution or stochastic-tail statistics.

No reviewed paper uses this project's exact all-time, common-edge
250/500/1000-bin L1 confidence-and-equivalence rule. Published particle-count
thresholds therefore cannot replace the registered CLEO test.

ADR 0006 prospectively defines the follow-up:

```text

target members: 100 per active resolution
reused previous members: 0
new model members: 400
```

All scientific settings and acceptance gates remain unchanged. The 512–8192
baseline receives no new members because its observed distribution bias is
already far outside the acceptance margin. Extending through 131,072 creates
two N/2N/4N candidate triples. If 100-member intervals alone remain too wide,
affected levels will be expanded toward 200; if high-resolution point bias or
adjacent differences remain too large, the next level is 262,144.

The planning estimate is about 6.25 CPU-hours of model work and 28.0 GB
(26.1 GiB) of new raw SCRATCH output. These are not Slurm requests. Exact account, partition,
nodes, tasks, CPUs, memory, walltime, concurrency and storage will be disclosed
before any submission.

The full source-by-source review, numerical projections, rationale and
