## 3. Numerical issue 1: an exact total near \(10^{19}\)

The configured concentration and \(10^{12}\,\mathrm{m^3}\) box imply:

```text
8388608000000000000 physical droplets
```

Float64 cannot distinguish every adjacent integer at this magnitude. The
first implementation multiplied float probabilities by the total, took floors
and summed them. It could lose hundreds of droplets because several different
large integers map to the same float.

The corrected implementation:

1. converts probabilities into high-resolution integer weights;
2. uses Python integers for quota floors and remainders;
3. gives residual droplets to the largest remainders;
4. breaks ties by bin index;
5. verifies the exact Python-integer total.

The final \(M_0\) total is therefore exact, not merely close within a relative
tolerance.

## 4. Numerical issue 2: nearly equal exponential values

With many narrow bins, directly calculating

```text
exp(-lower / scale) - exp(-upper / scale)
```

subtracts nearly equal numbers. At \(N_\mathrm{SD}=32768\), this could move a
calculated representative just outside its source bin.

The corrected bin integrals use:

- `expm1` for stable exponential differences;
- conditional first and second moments within a bin;
- series expansions for narrow dimensionless bin widths.

Float64 is used explicitly because NumPy `longdouble` has platform-dependent
precision. The scientific-array hash should not depend on whether the code ran
on macOS or Levante merely because one platform gives `longdouble` more bits.

The numerical sweep then passed for:

```text
64, 128, 256, 512, 1024, 4096, 16384, 32768 SDs
```

The 16-SD case was deliberately rejected because its \(M_6\) error was about
4.55%, above the registered 1% gate.

### Cross-platform hash finding

The gate also revealed a subtle but useful limitation. The macOS NumPy 1.26.4
scientific-array hash is `c2d02c94...551205`, while Levante NumPy 2.5.1
produces `11d4871d...c5d08`. Direct comparison found:

- 86 multiplicities with small integer redistributions while preserving the
  exact total;
- a maximum radius difference of `1.60e-18 m`;
- a maximum relative radius difference of `2.34e-13`;
- the same registered moment results to the checked tolerance.

The separate source-array and native-readback hashes also differ because CLEO
stores dimensionless radii and the reader re-dimensionalizes them. This is not
a physics-gate failure, but it means that “float64” alone does not promise
cross-platform byte identity. The permanent ensemble must generate each
resolution's bundle once on the pinned Levante stack and reuse that exact
native file after checksum verification.

### Bundle creation contract

One resolution gets one named, non-overwriting directory under the persistent
HOME bundle root. Input generation and native readback use the already
validated controlled path. Finalization requires:

- passing creation and native-readback schemas;
- matching \(N_\mathrm{SD}\);
- matching grid and superdroplet SHA-256 values across audit, readback and
  actual files;
- identical represented physical-droplet totals;
- all native readback gates true;
- a runtime configuration pointing at the exact bundle files;
- an initializer-source snapshot matching the creation audit.

The manifest records:

- a normalized scientific definition;
- project and pinned CLEO commits;
- Python, NumPy, platform, host and Slurm provenance;
- source and readback population fingerprints;
- relative path, size and SHA-256 for every required artifact.

Finalization removes write bits from every bundle file. An existing path or
manifest is never overwritten. A failed preparation remains visibly
incomplete and cannot pass `verify`.

### 17.3 Why the timestep screen was stopped before submission

The single pilot's formal fixed-bin L1 values at 3600 s were:

```text
250 bins:  0.2756078
500 bins:  0.3562021
1000 bins: 0.5346719
```

These values revealed a conceptual issue in the first screen analyzer. It
would have averaged scalar per-member L1 values. The registered scientific
estimand is instead:

```text
L1(ensemble-mean distribution)
```

and, because absolute value is nonlinear,

```text
L1(mean(g_j)) != mean(L1(g_j)).
```

The 25-member timestep screen was therefore **not submitted**. This was a
successful refusal gate, not a failed model run.

The corrected implementation:

1. saves every member's 250/500/1000-bin numerical and analytical arrays in
   `fixed_bin_distributions.npz`;
2. averages numerical distributions bin by bin;
3. computes L1 only after that averaging;
4. compares each timestep with 0.1 s using a deterministic 10,000-resample
   common-stream percentile bootstrap;
5. retains Student intervals for signed \(M_0\) and \(M_6\) member
   differences;
6. requires all registered times, bin grids, mass-drift and range-coverage
   gates to pass.

The same collision-stream labels are resampled together across timesteps to
make the comparison controlled and reproducible. The histories are still not
called paired because changing the timestep changes the collision-update
sequence.

Regression tests now include a deliberately constructed example in which both
members have L1 equal to 1 but their ensemble-mean distribution has L1 equal
to 0. The corrected repository passes:

```text

Bash parse: pass
pytest:     57 passed
```

The 25-row timestep matrix was regenerated from the corrected source
configuration. It remains metadata-only and records
